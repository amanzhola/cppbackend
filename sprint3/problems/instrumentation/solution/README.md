# 🔍 Instrumentation

## 📌 Описание

Задача посвящена профилированию приложения при помощи `gprof`.

Цель упражнения — сравнить несколько реализаций программы, определить самые медленные функции в каждой версии и выбрать наиболее производительное решение.

Для анализа использовались:

* компиляция через `g++ -O3 -pg`;
* запуск программы на одинаковом наборе входных данных;
* анализ файла `gmon.out`;
* построение отчётов через `gprof`.

---

## 🧠 Что изучается

| 📌 Тема              | 📖 Что проверяется                                    | ✅ Итог                          |
| -------------------- | ----------------------------------------------------- | ------------------------------- |
| `gprof`              | Анализ времени выполнения функций                     | Поиск горячих точек программы   |
| `-pg`                | Инструментирование приложения на этапе компиляции     | Сбор данных профилирования      |
| Flat Profile         | Определение самых затратных функций                   | Поиск кандидатов на оптимизацию |
| Сравнение реализаций | Анализ производительности нескольких версий программы | Выбор наиболее быстрого решения |

## ⚙️ Сборка

Находясь в папке решения:

```bash
cd ~/cppbackend/sprint3/problems/instrumentation/solution
```

Собрать программу:

```bash
g++ -O3 *.cpp -o app
```

## 🧠 Вывод

Профилирование показало, что разные структуры данных оказывают серьёзное влияние на производительность программы.

Версия `v2` значительно быстрее предыдущих реализаций и сокращает время выполнения почти в двадцать раз по сравнению с исходной версией.

Главная идея задания:

```text
Сначала измеряем.
Потом ищем горячие точки.
Только после этого принимаем решение об оптимизации.
```
