# 🔍 Profiling Applications

## 📌 Описание

Этот раздел относится к Sprint 3 / Sprint 19_20 и посвящён профилированию приложений на C++.

Здесь собираются мини-упражнения по измерению производительности, поиску узких мест, инструментированию кода и анализу времени выполнения отдельных частей программы.

---

| `lesson_5_10_code_instrumentation` | Инструментирование C++ кода через RAII-класс `LogDuration`, макрос `LOG_DURATION`, `std::chrono` и автоматический замер времени выполнения функций | Позволяет быстро находить медленные участки программы без внешнего профайлера | [README](lesson_5_10_code_instrumentation/README.md) |
| `lesson_6_10_compiler_profiler_friends` | Профилирование C++ программы через `g++ -pg`, файл `gmon.out`, отчёт `gprof`, flat profile, call graph и визуализацию через `gprof2dot + graphviz` | Показывает, как компилятор и профайлер работают вместе: компилятор добавляет профилировочный код, а `gprof` помогает найти горячие точки программы | [README](lesson_6_10_compiler_profiler_friends/README.md) |

| `lesson_8_10_flame_graphs` | Построение FlameGraph по данным `perf`: запись `perf.data`, просмотр через `perf report`, преобразование стеков через `perf script`, `stackcollapse-perf.pl`, `flamegraph.pl` и получение интерактивного `graph.svg` | Показывает, как перейти от статистического профиля к наглядной SVG-визуализации стеков вызовов и быстро увидеть самые широкие горячие участки программы | [README](lesson_8_10_flame_graphs/README.md) |
| `flamegraph` | Практическая задача по автоматическому построению FlameGraph для игрового сервера: запуск сервера, профилирование процесса через `perf record`, генерация нагрузки через `curl`, преобразование `perf.data` в `graph.svg` через `stackcollapse-perf.pl` и `flamegraph.pl` | Показывает полный production-like сценарий: профилировать не учебную функцию, а реальный серверный процесс под HTTP-нагрузкой и получать готовый SVG-граф горячих участков | [README](../../../sprint3/problems/flamegraph/solution/README.md) |
| `lesson_9_10_poor_mans_profiler` | Poor Man's Profiler: подключение `gdb` к уже работающему процессу, снятие стека вызовов через `bt`, отключение через `detach` и анализ горячих участков по повторяющимся backtrace | Показывает простой способ профилирования через отладчик без `perf`, FlameGraph и специального инструментирования программы | [README](lesson_9_10_poor_mans_profiler/README.md) |
