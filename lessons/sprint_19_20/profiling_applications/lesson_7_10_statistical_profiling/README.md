# 📈 Lesson 7/10 — Statistical Profiling

## 📌 Описание

В этом упражнении изучается статистическое профилирование через Linux Perf.

В отличие от предыдущего урока с `gprof`, здесь не требуется специальное инструментирование программы через `-pg`.

Профилировщик периодически снимает статистические выборки во время выполнения приложения и определяет, где процессор проводит большую часть времени.

---

## ⚠️ Важно

Данное упражнение выполнялось на виртуальной машине Linux в Yandex Cloud (YC).

Причина:

```text
WSL имеет серьёзные ограничения для perf.
```

Во многих версиях WSL:

* отсутствует полноценная поддержка аппаратных счётчиков;
* запрещён доступ к perf events;
* не работает часть функциональности `perf top`;
* возникают ошибки доступа даже при использовании sudo.

Поэтому для корректного прохождения урока рекомендуется использовать:

```text
Yandex Cloud VM
Ubuntu Server
Linux VPS
Локальную Linux-машину
```

## 🧠 Что изучается

| 📌 Тема               | 📖 Что происходит                                      | ✅ Итог                                   |
| --------------------- | ------------------------------------------------------ | ---------------------------------------- |
| `perf record`         | Записывает статистические выборки выполнения программы | Формируется профиль производительности   |
| `perf report`         | Анализирует собранные данные                           | Показывает горячие точки                 |
| `perf top`            | Отображает горячие функции в реальном времени          | Позволяет наблюдать выполнение программы |
| Statistical Profiling | Профилирование на основе выборки событий               | Не требует изменения исходного кода      |
| Hot Spots             | Поиск самых дорогих функций                            | Основа последующей оптимизации           |

## 🔍 Инструмент perf

Проверить наличие perf:

```bash
perf --version
```

Если команда отсутствует:

```bash
sudo apt update
sudo apt install -y linux-tools-common linux-tools-generic linux-cloud-tools-generic
```

Проверить снова:

```bash
perf --version
```

## ⚙️ Сборка

Перейти в папку урока:

```bash
cd ~/cppbackend/lessons/sprint_19_20/profiling_applications/lesson_7_10_statistical_profiling
```

Собрать программу:

```bash
g++ -O2 -g -fno-omit-frame-pointer main.cpp -o app
```

Параметры:

```text
-O2                     оптимизация
-g                      отладочная информация
-fno-omit-frame-pointer корректные стеки вызовов для perf
```

---

## ▶️ Проверка запуска

Перед профилированием убедиться, что программа работает:

```bash
./app
```

---

## 📊 Запись профиля

Записать профиль выполнения:

```bash
sudo perf record -g ./app
```

После завершения должен появиться файл:

```text
perf.data
```

Проверить:

```bash
ls -la perf.data
```

---

## 📄 Просмотр отчёта

Интерактивный режим:

```bash
sudo perf report -f
```

Управление:

```text
↑ ↓     перемещение
Enter   раскрытие функций
q       выход
```

---

## 🖥️ Текстовый отчёт

Самый удобный способ просмотра:

```bash
sudo perf report -f --stdio | head -80
```

Отчёт выводится прямо в терминал без интерактивного интерфейса.

## 🔥 Работа с perf top

Для использования `perf top` программа должна продолжать выполняться.

Увеличить количество итераций:

Было:

```cpp
for (int iteration = 0; iteration < 5; ++iteration)
```

Стало:

```cpp
for (int iteration = 0; iteration < 500; ++iteration)
```

Пересобрать:

```bash
g++ -O2 -g -fno-omit-frame-pointer main.cpp -o app
```

Запустить в фоне:

```bash
./app > app.log 2>&1 & APP_PID=$!; echo "PID=$APP_PID"
```

Проверить:

```bash
ps -p $APP_PID
```

Запустить мониторинг:

```bash
sudo perf top -p $APP_PID
```

Выход:

```text
q
```

---

## 🆚 Отличие от gprof

| gprof                            | perf                             |
| -------------------------------- | -------------------------------- |
| Требует `-pg`                    | Не требует изменения программы   |
| Создаёт `gmon.out`               | Создаёт `perf.data`              |
| Инструментирование               | Статистическая выборка           |
| Дополнительные накладные расходы | Минимальное влияние на программу |

## 🏁 Итог

```text

↓

↓
Найти горячие точки
↓

```

Главная идея урока:

```text
Статистическое профилирование позволяет анализировать производительность реальных приложений практически без вмешательства в их код.
```
