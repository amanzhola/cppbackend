## 📌 Описание

| 📌 Урок      | 📖 Что изучается                                                                                   | 🧠 Главная идея                                                                                | ✅ Итог                                                                |

| `lesson_6_7` | Автосохранение состояния игрового сервера через Boost.Signals2, Boost.Serialization, Conan и CMake | Сервер должен сохранять состояние после Tick, не смешивая игровую логику с кодом записи файлов | Подготовлены 3 практики: Observer, автосохранение и безопасная запись |

## 🔔 Практика 1 — `01_signals2_observer`

| 📌 Элемент          | 📖 Значение                                            | 🧠 Почему важно                                 |
| ------------------- | ------------------------------------------------------ | ----------------------------------------------- |
| `boost::signals2`   | Библиотека сигналов и слотов                           | Позволяет подписывать обработчики на события    |
| `Application::Tick` | Метод, который вызывает сигнал                         | Приложение сообщает, что произошёл игровой Tick |
| `DoOnTick`          | Подписка обработчика                                   | Позволяет внешнему объекту слушать приложение   |
| `scoped_connection` | Автоматическая отписка при выходе из области видимости | Защищает от забытых подписок                    |
| `30ms`, `15ms`      | Литералы времени из `std::literals`                    | Удобная запись миллисекунд                      |

Ожидаемый смысл практики:

```text
Application не знает, кто его слушает.
Application просто сообщает: произошёл Tick.
```

## 💾 Практика 2 — `02_autosave_state`

| 📌 Элемент             | 📖 Значение                                  | 🧠 Почему важно                                    |
| ---------------------- | -------------------------------------------- | -------------------------------------------------- |
| `GameState`            | Состояние игры: `tick_count`, `player_score` | Эти данные можно сохранить                         |
| `serialize`            | Метод сериализации Boost                     | Описывает, какие поля попадают в архив             |
| `SerializingListener`  | Слушатель Tick                               | Не меняет игру, а только реагирует на событие      |
| `save_period = 3500ms` | Период автосохранения                        | Сохранение происходит не каждый Tick, а по времени |
| `text_oarchive`        | Текстовый архив Boost                        | Записывает состояние в файл                        |

Главная схема:

```text
Application
↓ Tick
SerializingListener
↓
если прошло 3500ms
↓
Save()
↓
game_state.txt
```

## 🛡 Практика 3 — `03_safe_file_save`

| 📌 Элемент                      | 📖 Значение                           | 🧠 Почему важно                                       |
| ------------------------------- | ------------------------------------- | ----------------------------------------------------- |
| `game_state.txt.tmp`            | Временный файл                        | Сначала запись идёт не в основной файл                |
| `boost::archive::text_oarchive` | Сериализация состояния                | Сохраняет объект `GameState`                          |
| `std::filesystem::rename`       | Переименование `.tmp` в основной файл | Основной файл заменяется только после успешной записи |
| `LoadState`                     | Десериализация состояния              | Проверяет, что файл можно прочитать обратно           |

Главная схема:

```text
1. Пишем в game_state.txt.tmp
2. Закрываем файл
3. Переименовываем game_state.txt.tmp в game_state.txt
```

| Термин           | Расшифровка                         | Значение в уроке                                                                      |
| ---------------- | ----------------------------------- | ------------------------------------------------------------------------------------- |

| `Slot`           | слот                                | Обработчик события                                                                    |
| `REST API`       | Representational State Transfer API | HTTP-интерфейс для работы с ресурсами сервера                                         |

| ❌ Неправильно                                | ✅ Правильно                                |
| -------------------------------------------- | ------------------------------------------ |

## 🔨 Сборка всех практик одной командой

```bash
cd ~/cppbackend/lessons/sprint_20_20/serialization/lesson_6_7

for dir in 01_signals2_observer 02_autosave_state 03_safe_file_save; do
    echo "Building $dir"
    cd "$dir"

    rm -rf build
    mkdir build
    cd build

    conan install .. --output-folder=. --build=missing -s build_type=Release -s compiler.libcxx=libstdc++11

    cmake --build .

    cd ../..
done
```
