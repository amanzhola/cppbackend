# 💾 State Serialization

## 📌 Описание задания

| 📌 Задача             | 📖 Что требовалось реализовать                                             | 🧠 Практическая цель                                                              | ✅ Результат                                              |
| --------------------- | -------------------------------------------------------------------------- | --------------------------------------------------------------------------------- | -------------------------------------------------------- |
| `state_serialization` | Сохранение и восстановление состояния игрового сервера между перезапусками | Позволить серверу продолжить работу после остановки без потери игрового прогресса | Реализовано сохранение и загрузка полного состояния игры |

---

## 🗂 Основные требования задания

| 📌 Требование                        | 📖 Описание                         |
| ------------------------------------ | ----------------------------------- |
| `--state-file <path>`                | Путь к файлу состояния              |
| `--save-state-period <milliseconds>` | Интервал автоматического сохранения |
| Восстановление состояния             | Выполняется при старте сервера      |
| Автосохранение                       | Выполняется после Tick              |
| SIGINT                               | Сохранение перед завершением        |
| SIGTERM                              | Сохранение перед завершением        |
| Повреждённый файл                    | Завершение через `EXIT_FAILURE`     |

---

## 💾 Что сохраняется

| 📦 Подсистема     | 📖 Что входит в сохранение                       |
| ----------------- | ------------------------------------------------ |
| Игровой мир       | Собаки, потерянные предметы, игровые сессии      |
| Авторизация       | Игроки и токены игроков                          |
| Игровое состояние | Идентификаторы объектов и состояние сессий       |
| Сервер            | Полное состояние для последующего восстановления |

## ⚙️ Новые параметры запуска

| Параметр                   | Назначение                                     |
| -------------------------- | ---------------------------------------------- |
| `--state-file state.txt`   | Файл сохранённого состояния                    |
| `--save-state-period 1000` | Автосохранение каждые 1000 ms игрового времени |

Пример:

```bash
./game_server \
    --config-file data/config.json \
    --www-root static \
    --state-file state.txt \
    --save-state-period 1000
```

## 🔄 Как работает восстановление

| Шаг | Что происходит                               |
| --- | -------------------------------------------- |
| 1   | Сервер проверяет наличие файла состояния     |
| 2   | Если файл найден — выполняется `LoadState()` |
| 3   | Если файл отсутствует — создаётся новая игра |
| 4   | Игроки и токены восстанавливаются            |
| 5   | Игровые сессии восстанавливаются             |

---

## ⏱ Автосохранение

Схема:

```text
Tick
↓
RequestHandler
↓
on_tick_(delta)
↓
StateSaver
↓
SaveStateSafely()
```

Сохранение выполняется только после завершения Tick.

Это исключает сохранение частично обновлённого состояния.

---

## 🛡 Безопасное сохранение

Используется схема:

```text
state.txt.tmp
        ↓
rename
        ↓
state.txt
```

Порядок работы:

| Шаг | Действие                                |
| --- | --------------------------------------- |
| 1   | Создаётся временный файл                |
| 2   | Выполняется сериализация                |
| 3   | Файл закрывается                        |
| 4   | Выполняется `std::filesystem::rename()` |
| 5   | Старый файл заменяется новым            |

---

## 🚨 Завершение сервера

При получении:

```text
SIGINT
SIGTERM
```

выполняется:

```text
остановка io_context
↓
StateSaver::Save()
↓
завершение приложения
```

Это позволяет не потерять последнее состояние игры.
